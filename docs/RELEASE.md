# Release readiness: 1.0

> **`1.1.0` is released** (2026-11-28, tag `v1.1.0`, after `v1.1.0-rc.1`; section 7 is its record). **`1.0.0` is released** (2026-11-26, tag `v1.0.0`, GitHub release "Latest"). It was published first as release candidates (`v1.0.0-rc.1` to `-rc.3`); the final tag has the same sources as `-rc.3`. The checklists below are the record of how that decision was made and what was verified; the boxes still open in section 4 are the owner's or are planned for 1.0.1 or 1.x, not blockers of the release. What `1.0.0` freezes (the IPC protocol, the C ABI, the PHP API) is in the README.

What 1.0 claims, the evidence for each claim, what is known to be missing, and the checklist that decides it. Written at the end of M10 (2026-11-14). A claim without evidence in the right-hand column is not a claim.

## 1. What 1.0 is

A C++23 RFC 6455 WebSocket server core: sans-I/O protocol, multi-loop server on epoll, TLS (OpenSSL), permessage-deflate (RFC 7692), per-IP and global limits, a pub/sub broker, Prometheus metrics, a stable C ABI (`libwsrv`), the `wsrvd` sidecar and a pure-PHP client. Linux only. The C++ headers still live in `src/server/` until the C ABI fixes the public surface (ADR-0013); the C ABI (`include/wsrv/wsrv.h`) is the stable part.

## 3. Known limitations (stated, not hidden)

Each is either a documented decision or a follow-up with an owner decision pending.

- **Linux only** (epoll). On macOS and Windows develop with Docker Desktop or WSL2 and run the worker next to the daemon ([DEPLOYMENT.md](DEPLOYMENT.md) section 11). Not in 1.0: TCP IPC (a worker on the host talking to `wsrvd` in a container), which arrives in 1.1 (ADR-0038), and a native macOS server (kqueue), then Windows (M13), planned for a later 1.x. The PHP and JavaScript clients are tested on Apple Silicon macOS in CI.
- **Rooms from PHP work through the sidecar only.** `wsrvd` with `--broker=true` gives a PHP worker `Connection::subscribe` and `Worker::publish`, and any process can publish with `Wsrv\Publisher` over the HTTP endpoint (ADR-0028). The C ABI (`wsrv_publish` / `wsrv_subscribe`) and so the PHP-FFI embedded mode do not have rooms yet (ADR-0027 slice 2, planned as ABI 0.5).
- **permessage-deflate multiplies broadcast cost** per subscriber (ADR-0024 A2). Leave compression off for broadcast-heavy deployments, or lower `max_payload_bytes`.
- **Broker bounds are global**, not per user (ADR-0024 A4): an application serving strangers adds its own quota.
- **The admin listener has no authentication unless you set `admin_token_file`** (1.1, ADR-0041), and then only `/metrics` has it (`/healthz` and `/readyz` must stay open for probes); it has no `Host` check and no TLS (SECURITY_DESIGN T21). Keep it on loopback or behind a network policy, and set the token when a scraper reaches it over a network.
- **Metrics are counters and gauges only.** The histograms (`handshake_seconds`, `loop_lag_seconds`, `outbound_queue_bytes`) in OPERATIONS section 3 are planned; there is no loop-lag watchdog yet (SECURITY_DESIGN T16). **Decision: post-1.0**; the handlers run on the host thread, so a slow handler cannot stall an I/O loop.
- **From the second security review, still open (owner delegated the decisions to the assistant on 2026-11-22; items 1, 2, 3 and 5 of that review were fixed in #43):** (a) `SessionHandle` sends copy whole messages into posted closures, bounded only by the task-queue size: **built** (2026-11-23, ADR-0032): a per-loop byte budget `max_pending_send_bytes` (default 64 MiB), `BufferFull` when used up, `InvalidArgument` for a message larger than the whole budget. (b) No global buffered-bytes budget across connections (about 3 MiB per connection worst case with deflate, OPERATIONS 1.1): **accepted for 1.0 with the sizing formula documented; built for 1.1 (ADR-0040): `max_buffered_bytes`, a soft cap that sheds new connections with a 503**. (c) The zlib state of a connection lives for the connection once used: **accepted**, it is bounded by the window setting.
- **`IpLimits::sweep`** scans the whole table under its mutex on the accept path when the table is full (low risk at the default rates). **Accepted; amortise it when a benchmark or a report shows it matters.**
- **Per-IP limits can be switched off** with `0`. **Decision (2026-11-22): confirmed as the one exception** to "no unlimited value": behind a reverse proxy or NAT every user is one address, and the defaults would refuse real users. They are on by default, and the C keys of ADR-0016 A1 refuse `0` (no "off" there).
- **PHP binding**: the sidecar client and worker (with rooms and the HTTP `Publisher`), and the embedded FFI server (`Wsrv\Embedded\Server`, ADR-0025, with the `authenticate` handshake hook, no rooms yet). Examples: `examples/chat`, the Docker quickstart, and `docs/LARAVEL.md` (tried by hand against Laravel 13, not in CI). Not done: loop adapters (ReactPHP, Revolt). In development for 1.1, not released: a Laravel Broadcasting driver and the Pusher protocol for Laravel Echo (ADR-0042, `docs/LARAVEL_ECHO.md`). Published: `wsrv/client` on Packagist, `wsrvd` images on GHCR, checksummed binaries with build attestation on GitHub Releases (ADR-0026; `0.1.0-rc.2` was verified end to end from those artifacts on 2026-11-23). The PHP tests run on PHP 8.2 (the floor) and the latest release in `.github/workflows/php.yml`. The C consumer and the PHP binding pass Autobahn (run by hand with `tests/autobahn/run.sh --capi` and `--php`, not in CI: the 1.5 GB suite image is not part of the CI cost design).
- **Single-machine numbers** (PERFORMANCE.md): comparisons between loop counts, not capacity planning. There is no CI speed gate, by decision (PERFORMANCE.md "Regression gates").
