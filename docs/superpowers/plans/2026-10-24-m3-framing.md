# M3 Frame Codec Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Steps use checkbox syntax.

**Goal:** Everything between "the connection is upgraded" and "a complete, validated message": opcodes and close codes, masking, an incremental strict frame parser, a frame encoder, and a message assembler (buffered and streaming) with UTF-8 validation, size/fragment limits and control-frame interleaving, all sans-I/O and fuzzed.

**Architecture:** `protocol/` only (base + crypto + http deps, no OS). Data flows `bytes -> FrameParser -> FrameEvent (Header | Payload | End) -> MessageAssembler -> MessageEvent (Message | Part | Control)`. Errors carry the WebSocket close code to send (1002/1007/1008/1009). Pull-style API: callers call `next(input)` until it reports "need more bytes".

**Tech Stack:** C++23, GoogleTest, libFuzzer.

**Spec:** PROJECT_PLAN M3; REQUIREMENTS FR-F1..F8, FR-C3, FR-C4; PROTOCOL_EDGE_CASES §2-4 (EC-F01..F24, F25-F30, F37; EC-C05..C09; EC-U06 at message level); FRAGMENTATION.md §1; SECURITY_DESIGN T1, T5, T7; RFC 6455 §5, §7.4.

## Global Constraints
- All earlier gates stay green (Werror, tidy, include graph: protocol never includes OS headers, banned functions, header-check, sanitizers, hardening, fuzz in CI).
- Never allocate from a declared length; nothing grows beyond configured limits (frame payload 1 MiB, message 1 MiB, 1024 fragments by default); all wire-derived arithmetic is checked.
- Fail closed with the most specific close code at the first violation; after an error the component stays failed until reset.
- Parser result must be independent of chunking (byte-at-a-time == one shot).

## Review Focus
- 64-bit length edge cases (2^63, 2^64-1, minimal encoding boundaries 125/126, 65535/65536), declared-but-undelivered huge frames, integer overflow in message-size accumulation.
- Mask continuity across chunk boundaries and offsets 0-3; zero key; unaligned buffers.
- Fragmentation state machine: continuation without start, new data frame mid-message, control frames mid-message (incl. a UTF-8 sequence split around a Ping), Close mid-message, zero-length final fragment.
- UTF-8 failing at the first bad byte inside a fragment (not at FIN); streaming parts always end on code-point boundaries.
- Close payload rules: empty / 1 byte / invalid codes (1004-1006, 1015, <1000, 1016-2999, >=5000) / reason > 123 bytes / invalid UTF-8 reason.

### Task 1: Opcodes, close codes, failures, close payload
**Files:** Create `src/protocol/opcode.hpp`, `src/protocol/close_code.hpp/.cpp`, `src/protocol/failure.hpp`; Test `tests/protocol/close_code_test.cpp`, `tests/protocol/opcode_test.cpp`.
**Produces:**
`enum class Opcode : std::uint8_t { Continuation=0x0, Text=0x1, Binary=0x2, Close=0x8, Ping=0x9, Pong=0xA }; constexpr bool is_control(Opcode); constexpr bool is_known_opcode(std::uint8_t); constexpr std::optional<Opcode> opcode_from_wire(std::uint8_t)`.
`enum class CloseCode : std::uint16_t { Normal=1000, GoingAway=1001, ProtocolError=1002, UnsupportedData=1003, NoStatusReceived=1005, AbnormalClosure=1006, InvalidPayload=1007, PolicyViolation=1008, MessageTooBig=1009, MandatoryExtension=1010, InternalError=1011, ServiceRestart=1012, TryAgainLater=1013, BadGateway=1014, TlsHandshake=1015 }; constexpr bool is_valid_on_wire(std::uint16_t)`.
`struct ProtocolFailure { CloseCode code; std::string_view reason; }; template <class T> using FrameResult = std::expected<T, ProtocolFailure>;`
`struct ClosePayload { std::uint16_t code; std::string_view reason; /* views into the input */ }; FrameResult<std::optional<ClosePayload>> parse_close_payload(ByteView)` (empty payload -> nullopt = no status); `std::size_t encode_close_payload(MutableByteView, CloseCode, std::string_view reason)` (reason truncated at a UTF-8 boundary to 123 bytes).
- [ ] RED tests: opcode table over all 16 values; close-code validity over all 65536 values against an independent definition (EC-C07/C08); `parse_close_payload`: empty -> no status, 1 byte -> 1002 (EC-C06), valid code only, code+reason, reason 123 ok / 124 -> 1002 (EC-C09), invalid UTF-8 reason -> 1007 (EC-C09/U08), forbidden codes -> 1002; encode round trip and truncation never splits a code point.
- [ ] GREEN; commit.

### Task 3: Frame header, encoder, incremental parser
**Files:** Create `src/protocol/frame.hpp`, `src/protocol/frame_writer.hpp/.cpp`, `src/protocol/frame_parser.hpp/.cpp`; Tests `tests/protocol/frame_writer_test.cpp`, `tests/protocol/frame_parser_test.cpp`.
**Produces:**
`struct FrameHeader { bool fin; bool rsv1,rsv2,rsv3; Opcode opcode; bool masked; std::uint64_t payload_length; MaskKey mask_key; };`
`constexpr std::size_t kMaxHeaderSize = 14; Result<std::size_t> encode_header(MutableByteView out, const FrameHeader&)` (minimal length encoding; control frame > 125 or non-FIN -> InvalidArgument).
`struct FrameParserConfig { bool expect_masked = true; bool allow_rsv1 = false; std::uint64_t max_frame_payload = 1 MiB; };`
`struct FrameEvent { enum class Kind { Header, Payload, End } kind; FrameHeader header; ByteView payload; }`
`class FrameParser { explicit FrameParser(FrameParserConfig); FrameResult<std::optional<FrameEvent>> next(MutableByteView& input); void reset(); }` — `next` consumes from the front of `input` (advancing it), unmasks payload IN PLACE and returns a view into the caller's buffer; nullopt = need more bytes. Header validation order: reserved opcode, rsv2/rsv3, rsv1 policy (also never on control/continuation), mask expectation, control rules (<=125, FIN), length encoding (minimal form, MSB of 64-bit), `max_frame_payload` (-> 1009) — all at the moment the header is complete, before any payload.
- [ ] RED tests: RFC vectors (masked/unmasked Hello, ping, 256-byte and 65536-byte binary headers); EC-F01..F07, F12 (zero-length), F13..F17 (every split, byte-at-a-time, many frames per read, masks across chunks), F21/F22 (2^63, 2^64-1 lengths, huge declared frame never buffered), F24; encoder: minimal encodings at 0,125,126,65535,65536; encoder->parser round trip for random frames; failed parser stays failed until reset.
- [ ] GREEN; commit.

### Task 4: Message assembler (buffered)
**Files:** Create `src/protocol/message_assembler.hpp/.cpp`; Test `tests/protocol/message_assembler_test.cpp`.
**Produces:** `struct AssemblerConfig { std::size_t max_message_size = 1 MiB; std::size_t max_fragments = 1024; bool streaming = false; };` `enum class MessageType { Text, Binary }`;
`struct MessageEvent { enum class Kind { Message, Part, Control } kind; MessageType type; ByteView data; bool final; Opcode control_opcode; }` (views valid until the next call);
`class MessageAssembler { explicit MessageAssembler(AssemblerConfig); FrameResult<std::optional<MessageEvent>> handle(const FrameEvent&); void reset(); }`.
Rules: Idle+Continuation -> 1002 (F09); InMessage+Text/Binary -> 1002 (F10); control frames interleave without touching message state (F11, F25), their payload (<=125) is collected and emitted at End; size via `checked_add` -> 1009 at the fragment that exceeds (F19, F21); fragment count -> 1008 (F20, F28); text validated incrementally, failing with 1007 at the first bad byte inside a fragment (U06); zero-length final continuation completes (F37); Close mid-message is delivered as Control and the partial message is discarded by `reset_message()` (F26).
- [ ] RED tests for each EC row above through parser+assembler; message equality for every fragmentation/chunking of a sample (property); text split at every byte around a Ping; limits exactly at / one over.
- [ ] GREEN; commit.

## Self-review
FR-F1..F8 covered (F8 streaming = Task 5); FR-F7 outbound fragmentation/scheduling and ping/pong replies belong to M4 (session). EC-F18/F23 (very large messages, disconnect mid-frame) are connection-level (M6). EC-C01..C04, C10..C18 are session behaviour (M4). Ruling: parser unmasks in place and hands out views into the caller's buffer (zero copy) — the buffer must stay alive and unmodified until the next `next()` call; documented on the API.
