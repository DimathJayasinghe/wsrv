# M4 Protocol Session Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Steps use checkbox syntax.

**Goal:** The sans-I/O `ProtocolSession`: everything RFC 6455 requires above single frames and messages. Auto Pong, the close handshake, heartbeat and idle/pong/close/incomplete-message timeouts, control- and data-frame rate limits, and a bounded outbound scheduler with auto-fragmentation where control frames jump ahead of data at frame boundaries.

**Architecture:** `protocol/` only (no OS headers). `bytes -> FrameParser -> MessageAssembler -> ProtocolSession -> SessionEvent`; `send_*()/close()/tick() -> OutboundScheduler -> pending_output()`. The session owns the state machine `Open -> Closing -> Closed` (the handshake is done by the caller; the session is constructed after the 101 response). Deterministic: same bytes + same ticks give the same output. Time enters only through `tick(now)` and the constructor.

**Tech Stack:** C++23, GoogleTest, libFuzzer.

**Spec:** PROJECT_PLAN M4; REQUIREMENTS FR-F7, FR-F10, FR-F11, FR-C1..C6 and the limits table (§4); PROTOCOL_EDGE_CASES EC-F11/F12/F15 (rates), F26/F27/F30, F31, F32, EC-C01..C04, C10..C17 (not C18, which is server-level); FRAGMENTATION.md §2.1/2.3; SECURITY_DESIGN T7; RFC 6455 §5.5, §5.5.1-5.5.3, §7.

## Global Constraints
- All earlier gates stay green (Werror, tidy, include graph, banned functions, header-check, ASan/UBSan/TSan, fuzz corpus replay).
- Every queue is bounded with a defined overflow action: outbound data queue 1 MiB (`Backpressure`), one pending Pong (latest wins, EC-C02), one pending Ping, one Close. The wire buffer holds at most one data frame plus the control frames.
- Nothing is sent after the Close frame (RFC 6455 §5.5.1). Nothing is delivered after the peer's Close (FR-C5, EC-C10).
- Exactly one `Closed` event per session (EC-C11, C15); exactly one Close frame on the wire.
- No locks, no threads, no clock reads: `tick(now)` only. `feed`-time rate limits use the time of the last tick.
- Server role only (frames out are unmasked, frames in must be masked). Client role is a later extension (needs `IRandom` for mask keys).

## Review Focus
- Ping in the middle of a fragmented message with a UTF-8 character split around it: Pong sent, message completes (EC-C01, F25).
- Close in every state: Open (peer-initiated), Closing (we initiated, peer replies), simultaneous (EC-C11), peer never replies (EC-C12), peer closes TCP right after its Close (EC-C13), peer EOF with no Close (1006).
- Ping flood: only the latest Pong is kept; control-frame rate limit closes with 1008 (EC-C02, C04).
- Large outbound message while a Ping/Close is queued: the control frame is emitted at the next frame boundary, never inside a frame (EC-F32); partial `consume_output` at every split point.
- After any failure the session emits exactly one `ProtocolError` and one `Closed`, sends exactly one Close frame with a code that is legal on the wire, and ignores further input.
- Time: backwards or equal ticks, a tick far in the future, all timers disabled (0), timer firing in the same tick as input.

```cpp
struct OutboundConfig {
    std::size_t max_frame_payload = 64 * 1024;   // auto-fragmentation size (EC-F31)
    std::size_t max_queued_bytes = 1U << 20;     // queued data payload bytes + 16 per message
};
class OutboundScheduler {
public:
    explicit OutboundScheduler(OutboundConfig);
    Result<void> enqueue_message(Opcode text_or_binary, ByteView payload); // Closing | Backpressure | BufferFull(never fits)
    Result<void> queue_ping(ByteView payload);        // <=125, one slot: Backpressure if occupied
    void queue_pong(ByteView payload);                // <=125 asserted by caller; replaces an older unsent Pong
    void queue_close(std::optional<std::uint16_t> code, std::string_view reason); // idempotent; drops unstarted data
    ByteView pending();                               // refills at a frame boundary; empty = nothing to write
    void consume(std::size_t n);
    bool close_queued() const; bool close_flushed() const; bool has_pending() const;
};
```

### Task 3: ProtocolSession — inbound, Pong, close handshake
**Files:** Create `src/protocol/session.hpp/.cpp`; Test `tests/protocol/session_test.cpp` (scripted peer: builds masked client frames, parses server output with a client-mode `FrameParser`); add to CMake.
**Consumes:** `FrameParser`, `MessageAssembler`, `OutboundScheduler`, `parse_close_payload`, `TimePoint`.
**Produces:**
```cpp
enum class SessionState : std::uint8_t { Open, Closing, Closed };
struct SessionConfig {
    FrameParserConfig parser; AssemblerConfig assembler; OutboundConfig outbound;
    std::chrono::milliseconds ping_interval{30000}, pong_timeout{10000}, idle_timeout{60000},
        close_timeout{5000}, incomplete_message_timeout{30000};   // 0 disables ping/idle/incomplete
    std::uint32_t max_control_frames_per_second = 100, max_data_frames_per_second = 10000;
};
struct SessionEvent {
    enum class Kind : std::uint8_t { Message, Part, Ping, Pong, ProtocolError, Closed };
    Kind kind; MessageType type; ByteView data; ByteView tail; bool final;   // Message/Part, Ping/Pong payload in data
    CloseCode code; std::string_view reason; bool clean;                       // ProtocolError (code,reason); Closed (all three)
};
class ProtocolSession {
public:
    ProtocolSession(SessionConfig, TimePoint now);
    std::optional<SessionEvent> next_event(MutableByteView& input);  // consumes input; views valid until the next call
    void tick(TimePoint now);
    Result<void> send_text(std::string_view); Result<void> send_binary(ByteView); Result<void> send_ping(ByteView);
    Result<void> close(CloseCode, std::string_view reason);          // idempotent
    void on_transport_closed();                                       // peer EOF / write failure
    ByteView pending_output(); void consume_output(std::size_t);
    SessionState state() const noexcept;
};
```
Rules: Ping -> queue Pong with the same payload + `Ping` event; Pong -> clear the heartbeat wait + `Pong` event; Close -> validate (`parse_close_payload`, failure -> that code), discard the partial message, echo (empty payload -> empty Close, else same code, EC-C05), state Closing, input ignored from then on; `Closed` event when our Close is fully written (clean=true) — or at once if the peer EOFs (EC-C13). Our own `close()`: queue Close, discard partial message, keep parsing until the peer's Close but drop data/Ping events (EC-C10). A protocol failure: queue Close(code) once, emit `ProtocolError`, ignore input, `Closed(clean=false)` when flushed. `Closed.code` = the peer's code, else 1005 when it sent none, else the code we sent for a local/failure close, else 1006 (EOF/timeout with nothing). After Closed: input discarded, no output.
- [ ] RED tests: Ping -> identical Pong, also between fragments with a split UTF-8 character (EC-C01, F25); Pong event; unsolicited Pong ignored for liveness but surfaced (EC-C03); peer Close with code+reason echoed, Closed after flush (EC-C05/C08/C13 variants: empty payload, 1000, 3000, 4999); invalid Close payloads (1 byte, code 1005/1006/1015/999/5000, bad UTF-8 reason, 124-byte reason) -> 1002/1007 ProtocolError + Close sent (EC-C06..C09); data after peer Close produces no events (EC-C10); local `close()` then peer Close -> clean Closed once; simultaneous Close (EC-C11); `close()` twice and from "inside" the Closed handling (EC-C15); partial message + Close -> never delivered (EC-F26); streaming mode parts; protocol failure from the assembler (1002/1007/1009) sends exactly one Close and ignores later input; peer EOF with and without Close (1006, EC-F23, N04).
- [ ] GREEN, commit.

### Task 5: Timers and rate limits
**Files:** `session.cpp`, `session_test.cpp`.
**Rules:** `tick(now)` never moves time backwards (ignore earlier values). Idle: no complete frame for `idle_timeout` -> `close(1001)` (EC-C17). Heartbeat: if `now - max(last_frame, last_ping) >= ping_interval` and no ping is outstanding -> queue an empty Ping; no Pong within `pong_timeout` -> close 1001 (EC-C16). Incomplete message: `in_message()` for longer than `incomplete_message_timeout` -> 1008 (EC-F27). Close timeout: Closing for `close_timeout` -> `Closed(clean=false, 1006)` (EC-C12). Rates: per one-second window starting at the last window reset in `tick`: more than `max_control_frames_per_second` control frames or `max_data_frames_per_second` data frame headers -> 1008 (EC-C04, F12, F28). Disabled (0) timers never fire.
