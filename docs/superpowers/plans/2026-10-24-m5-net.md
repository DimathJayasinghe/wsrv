# M5 Networking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Steps use checkbox syntax.

**Goal:** All OS-specific code, behind interfaces: RAII file descriptors, a thin injectable `ISyscalls` layer, an epoll `IPoller`, a hashed timer wheel, a single-threaded `EventLoop` with cross-thread `post()` + wake-up, a plain TCP transport, a listener and an `Acceptor` with the `EMFILE` reserve-fd trick. Loop tests cover timers, wake-ups and EINTR/EAGAIN/EMFILE/EPIPE fault injection.

**Architecture:** `src/net/` only (depends on `base`, never on `protocol/`). Everything that touches the kernel goes through `ISyscalls` (real: `LinuxSyscalls`; tests: `FakeSyscalls` with scripted results), so every `errno` path is testable without a real failing kernel. The loop owns a poller, a timer wheel and a task queue; fd registrations are keyed by handle + generation, never by raw fd (EC-N12).

**Tech Stack:** C++23, Linux (epoll, eventfd, accept4), GoogleTest, TSAN for the cross-thread paths.

**Spec:** PROJECT_PLAN M5; ARCHITECTURE §3.5, §5, §6; ADR-0003, ADR-0004; TESTING_STRATEGY §37 (Syscall layer); CODING_STANDARDS lines 66-67 (capture errno immediately; wrap syscalls; retry EINTR); PROTOCOL_EDGE_CASES EC-N01..N08, N12, N13, N14, N15, N16 (monotonic clock), N20; SECURITY_DESIGN T3 (fd exhaustion).

## Global Constraints
- All earlier gates stay green; `tools/check_includes.py`: only `net/` may include OS headers; `net` must not include `protocol/`.
- `errno` is captured immediately into an `Error` (no later reads); `EINTR` is retried inside the syscall wrappers; `EAGAIN` is a normal `WouldBlock` result, not a failure.
- No allocation sized from peer data; every queue (posted tasks, timers, registrations) has a configured bound and a defined overflow result.
- No exceptions on runtime paths: callbacks are `noexcept`-contract (documented), the loop never lets one escape.
- Only the monotonic clock for deadlines (EC-N16). `SIGPIPE` never raised: `MSG_NOSIGNAL` on every send (EC-N03).
- Fairness: one loop iteration processes at most `max_events_per_iteration` fd events and `max_tasks_per_iteration` posted tasks.
- Cross-thread access to a loop only via `post()` and `stop()` (the documented thread-safe surface); everything else is loop-thread-only.

## Review Focus
- `EMFILE`/`ENFILE` on accept: the pending connection is accepted and closed with the reserve fd (the kernel queue drains), the reserve is restored, the acceptor backs off, no busy loop (EC-N05).
- Stale events: an fd closed and its number reused in the same iteration must not deliver the old registration's event to the new owner (EC-N12).
- `post()` flood from many threads: bounded; excess is rejected with an error, never unbounded growth (EC-N14); tasks posted from inside a task run next iteration, not recursively.
- Timer storms: a thousand timers due in one tick are processed within the iteration budget without starving fd events (EC-N15); cancel of an already-fired/cancelled timer is harmless; a timer scheduled for the past fires on the next iteration.
- Partial write / `EAGAIN` / `EPIPE` / `ECONNRESET` mapping: `EPIPE` never kills the process; EOF (`read` = 0) is distinguishable from "would block".
- Wake-up: `stop()` and `post()` from another thread interrupt a blocked `epoll_wait`; a wake-up posted before `run()` starts is not lost; the eventfd counter is drained fully.

### Task 3: `TimerWheel` (pure, no OS)
**Files:** Create `src/net/timer_wheel.hpp/.cpp`; Test `tests/net/timer_wheel_test.cpp`.
**Produces:**
```cpp
using TimerId = std::uint64_t;                    // 0 is never valid; ids are not reused
struct TimerWheelConfig { std::chrono::milliseconds tick{10}; std::size_t slots = 256; std::size_t max_timers = 1U << 20; };
class TimerWheel { public:
  TimerWheel(TimerWheelConfig, TimePoint now);
  Result<TimerId> schedule(TimePoint deadline);   // BufferFull at max_timers; deadline in the past => fires on the next advance
  bool cancel(TimerId);                           // false if unknown / already fired
  void advance(TimePoint now, std::vector<TimerId>& expired);   // appends due ids, earliest first; at most `limit`? (see budget below)
  std::optional<TimePoint> next_wake() const;     // a lower bound on the next deadline (may be early, never late)
  std::size_t size() const;
};
```
Budget: `advance(now, expired, max)` returns at most `max` ids and keeps the rest due for the next call (EC-N15).
- [ ] RED: single timer fires exactly at its deadline tick (not before); cancel before fire / after fire / twice / unknown; past deadline; deadline beyond one wheel revolution (multi-round); same-slot collisions keep order by deadline; bound enforced; budget leaves the remainder for the next call; `next_wake` never later than the earliest deadline; **model test**: 20,000 random schedule/cancel/advance operations compared against a `std::multimap<TimePoint, TimerId>` reference (fixed seed), including large clock jumps.

**Produces:**

```cpp
enum class PollEvents : std::uint8_t { None = 0, Read = 1, Write = 2, Error = 4, Hangup = 8 };   // + bitwise ops
struct PollEvent { std::uint64_t token; PollEvents events; };
class IPoller { public: virtual ~IPoller() = default;
  virtual Result<void> add(int fd, PollEvents interest, std::uint64_t token) = 0;     // edge-triggered
  virtual Result<void> modify(int fd, PollEvents interest, std::uint64_t token) = 0;
  virtual Result<void> remove(int fd) = 0;
  virtual Result<std::size_t> wait(int timeout_ms, std::span<PollEvent> out) = 0; };   // 0 = timeout; EINTR => 0 events
class EpollPoller final : public IPoller { EpollPoller(ISyscalls&); static Result<EpollPoller> create(ISyscalls&); };
```
- [ ] RED (contract): a readable socket reports `Read` with its token; edge-triggered: not reported again until new data (EC-N07 discipline test); `Write` interest reports writability once; peer close reports `Hangup`/`Read`; `modify` changes interest; `remove` stops events; double add -> error; `wait` honours the timeout (0 and a few ms) and the `out` size (more ready fds than slots are delivered over successive calls); EINTR from `epoll_wait` (fault-injected) yields 0 events, not an error.

### Task 5: `EventLoop`
**Files:** Create `src/net/event_loop.hpp/.cpp`; Test `tests/net/event_loop_test.cpp`.
**Consumes:** `IPoller`, `TimerWheel`, `ISyscalls`, `IClock`.
**Produces:**
```cpp
struct EventLoopConfig { std::size_t max_events_per_iteration = 256, max_tasks_per_iteration = 256, max_queued_tasks = 4096, max_watches = 65536, max_timers = 1U << 20; };
using Task = std::function<void()>;
class IEventHandler { public: virtual ~IEventHandler() = default; virtual void on_event(PollEvents) noexcept = 0; };
struct WatchHandle { std::uint32_t index; std::uint32_t generation; };    // not the fd number (EC-N12)
class EventLoop { public:
  static Result<std::unique_ptr<EventLoop>> create(ISyscalls&, const IClock&, EventLoopConfig = {});
  void run(); void run_once(std::chrono::milliseconds max_wait);    // loop thread
  void stop();                                                       // any thread
  Result<void> post(Task);                                           // any thread; BufferFull at max_queued_tasks
  Result<TimerHandle> run_after(std::chrono::milliseconds, Task); bool cancel(TimerHandle);          // loop thread
  Result<WatchHandle> watch(int fd, PollEvents interest, IEventHandler&); Result<void> rewatch(WatchHandle, PollEvents); void unwatch(WatchHandle);   // loop thread
  bool in_loop_thread() const;
};
```
Rules: a posted task wakes the loop through the eventfd (the counter is drained fully each iteration); tasks posted by a running task run next iteration; `unwatch` makes events for that handle in the current batch be dropped (generation bump); events whose token generation does not match are dropped; exceptions from tasks are caught and counted, never propagated (a `std::function` may throw; the loop is the boundary); timers due beyond the iteration budget carry over.
- [ ] RED: `run_once(0)` with nothing to do returns; `post` from the loop thread runs once, in order; `post` from another thread wakes a blocked `run()` (TSAN) and `stop()` ends it; a post made before `run()` is not lost; queue bound rejects the (N+1)th post and recovers after draining; many threads posting 100,000 tasks in total: all run exactly once (TSAN); tasks posted from a task run in the next iteration; a timer fires after the clock (FakeClock) passes its deadline, `cancel` prevents it, cancel inside its own callback is safe; 1,000 timers due at once with budget 100 take 10 iterations and fd events are still served in between; watch delivers `Read` for data written to a socketpair; `unwatch` inside a callback drops the remaining events of the batch for that handle; **fd reuse**: close + new socket gets the same number, the old handle's stale event is not delivered to the new owner; callback that throws does not escape `run_once`; `FakeSyscalls` `epoll_wait` EINTR does not stop `run()`.
- [ ] GREEN, commit.
