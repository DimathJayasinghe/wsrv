# M6 Single-Thread Server Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Steps use checkbox syntax. Teaching mode: before each task say what / why / how; after the milestone write lesson 11.

**Goal:** A working single-loop WebSocket server: accept, HTTP handshake, `ProtocolSession` over a `PlainTransport`, a handler API, bounded write path with backpressure, all limits enforced, graceful shutdown on signals, an echo example, the Autobahn core suite at 100 %, and a browser demo UI.

**Architecture:** `src/server/` composes `net` (loop, transport, acceptor) and `protocol`/`http` (sans-I/O). `Connection` is glue only (DESIGN_PATTERNS S): it owns a transport, a `HandshakeDriver` then a `ProtocolSession`, an inbound buffer and timers, and reaches the loop through a narrow `IConnectionHost` interface, so it is unit-tested with a fake host and fake transport (no kernel). Teardown is deferred to a safe point (ADR-0013).

**Tech Stack:** C++23, Linux, GoogleTest, ASAN/UBSAN + TSAN, Autobahn|Testsuite in docker compose.

**Spec:** PROJECT_PLAN M6; ARCHITECTURE sections 3.6, 5, 6, 7; ADR-0013 (new), ADR-0003/0007; FR-S1..S6, FR-C2, FR-C5, FR-C6, FR-H7, FR-H8, FR-F12; REQUIREMENTS section 4; EC-A01..A06, EC-N02, N04, N07..N09, N11, N17, N18, EC-H17..H22, EC-C11..C18; SECURITY_DESIGN T2, T3, T7, T13, T14, T16; FRAGMENTATION sections 1.3, 2.2.

## Global Constraints
- All earlier gates stay green. `server/` may include `base protocol net extensions`; no OS headers outside `net/` (signals and `getpeername` go through `ISyscalls`).
- No locks in connection code. One loop thread; `Server` is single-loop in M6 (the loop group is M7). Cross-thread only `post()`/`stop()`.
- Every buffer bounded: inbound buffer (starts <= 4 KiB per idle connection, grows only to what a frame needs, never past the configured frame limit), outbound queue (`OutboundConfig`), handshake head (`HttpLimits`).
- Limits are never raised to pass a test. Autobahn-specific larger limits live ONLY in the Autobahn example config, within the hard ceilings, with a comment saying why.
- Log lines contain only sanitised peer text (T14). A connection id (64-bit counter) appears in every line.
- Per-IP caps, handshake rate limit and the global buffered-bytes budget are M10 (`LimitsEnforcer`), not here. The global connection cap is here (FR-S1).

## Review Focus
- **View lifetime:** echo `send_text(view_from_event)` is safe (the scheduler copies). ASAN test for buffered, streaming and large fragmented messages.
- **Edge-triggered read budget:** stopping at the fairness budget with data left must reschedule the read (a `defer`-ed re-read), or the connection hangs until new data arrives (EC-N07/N08). Flooding client next to a quiet neighbour.
- **Teardown inside `on_event`:** the connection never destroys itself; the table destroys it after the batch. ASAN test closing from every callback.
- **Ordering:** `tick(now)` before each read batch; close order is write -> `consume_output` -> `next_event(empty)` to get `Closed` -> `shutdown_write` -> unwatch -> close fd. `on_close` exactly once, only if `on_open` ran.
- **Slow consumer:** `close(1008)` succeeds with a full data queue; a peer that never reads is dropped by the write-stall timer.
- **Handshake phase:** the 101 may be written partially; bytes after the request head stay in a mutable buffer (frames are unmasked in place, EC-H19); handshake timeout (EC-H20); client gone mid-101 (EC-H21).
- **Handler barrier:** a throwing handler (std::exception and non-std) closes 1011 and the server keeps serving.

### Task 4: `Connection`
**Files:** Create `src/server/connection.hpp/.cpp`, `src/server/connection_host.hpp`; Test `tests/support/fake_transport.hpp`, `tests/server/connection_test.cpp`.
**Produces:** `IConnectionHost` (ISP: `watch/rewatch/unwatch`, `run_after/cancel`, `defer`, `now`, `log`, `retire(ConnectionId)`); `Connection : IEventHandler, Session`. Phases `Handshaking -> Open -> Closing -> Closed` (ARCHITECTURE section 7). On readable: `tick`, then read until `WouldBlock` or the read budget (budget exhausted -> `defer` a re-read), feed the driver/session, deliver events to the handler inside the barrier. On writable / after any send: flush `pending_output` until `WouldBlock`; arm `Write` interest only while output is pending (EC-N02). Timers: handshake, 1 s session tick, write stall. Close sequence per Review Focus. Slow-consumer policy.
- [x] RED (FakeTransport + fake host + FakeClock): handshake byte-by-byte then echo; 101 written in 3 partial writes; peer vanishes mid-101 (no `on_open`, EC-H21); handshake timeout; message in the same read as the head; budget exhaustion reschedules; partial writes arm/disarm `Write`; `WouldBlock` mid-flush; EOF mid-message (EC-N04); peer Close echoed, `on_close` once (EC-C11); close timeout forces transport close (EC-C12); write stall closes; throwing handler (std and non-std) -> 1011 and `on_close` once (EC-A01); `close()` inside `on_open`, `on_text`, `on_close` (EC-A03, A06, C15); send after close -> `Closing`; idle and heartbeat timeouts (EC-C16, C17); `retire` is called exactly once.
- [x] GREEN, commit.
