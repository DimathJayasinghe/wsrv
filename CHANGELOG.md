# Changelog

Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versioning: [Semantic Versioning](https://semver.org/) for the C++ API and the PHP package; the C ABI has its own `major.minor` (`wsrv_abi_version()`), additive within a major.

Known gaps are listed in [docs/RELEASE.md](docs/RELEASE.md). `0.1.0-rc.1` and `0.1.0-rc.2` were early pre-releases of what is below.

## [Unreleased]

### Added
- **The adoption layer:** [docs/GETTING_STARTED.md](docs/GETTING_STARTED.md) (a five-minute Docker quickstart and one path per stack), [docs/EVIDENCE.md](docs/EVIDENCE.md) (each claim, the command that checks it, the last result and what it does not show), an "Is wsrv right for you?" section in the README that names when Reverb, Workerman or Swoole is the better choice, and a browser page in `examples/docker` (`web/index.html`, served by a new `web` service on `http://localhost:8000`, using the JavaScript client) so the quickstart ends in something you can watch, including a reconnect and rejoin after `docker compose restart wsrvd`. `docker/HUB.md` now covers TCP IPC, generated tokens, the admin token and the buffer budget. Lesson 55.
- **TCP transport for the IPC link** (ADR-0038), so a worker on macOS, Windows or another machine can reach a `wsrvd` in Docker, WSL2 or a VM without a Unix socket: `wsrvd` keys `ipc_port` (0 to 65535, 0 = the kernel chooses and `ipc_ready` logs it) and `ipc_host` (an address literal, default `127.0.0.1`); `--ipc-port`, `--ipc-host`, `WSRVD_IPC_PORT`, `WSRVD_IPC_HOST`. Exactly one of `ipc_socket` and `ipc_port`. Over TCP the token is mandatory and must be one that the new `wsrvd --generate-token=FILE` made (256 random bits in a fixed form with a checksum, mode 0600, never overwrites; a length floor cannot tell a random token from a long guessable one, and the token is the only authentication because there is no peer uid), the link is plaintext (a non-loopback bind logs the warning `ipc_plaintext`), `TCP_NODELAY` and keepalive are set, connections that have not said HELLO wait in a room of 8 with their own deadlines instead of holding the single application slot (the first accepted HELLO wins, the oldest is evicted when a ninth arrives), and a peer the daemon turns away (busy, rejected HELLO, replaced) is sent its status and then lingered with, not reset, so Windows and macOS workers can read it. The IPC protocol is unchanged (0.3); a client written for the Unix socket works over TCP by changing how it connects.
- PHP: `Client::connect('tcp://host:port', $token)` (and `Supervisor::forSocket`, `Client::dial`, `Client::isTcpEndpoint`), with `TCP_NODELAY`. A `windows` CI workflow runs the PHP client tests on a real Windows runner; `php_tcp_interop` runs a worker against a real `wsrvd` over TCP.
- `examples/host-worker`: the daemon in Docker with TCP IPC published on the host's loopback, a token created in a volume, and a worker script for the host. Log events `ipc_plaintext`, `ipc_keepalive`, `app_replaced` (warn), `app_waiting` and `ipc_linger_full` (debug) (OPERATIONS section 2).
- **A global budget for the bytes connections buffer** (ADR-0040): `max_buffered_bytes` (config file, `--max-buffered-bytes`, `WSRVD_MAX_BUFFERED_BYTES`, `wsrv_config_set`; default 1 GiB, 1 byte to 1 TiB, no unlimited value). It counts, over all connections, the bytes of messages that started and are not delivered plus the bytes waiting to be written (queued or framed and not yet taken by the socket). While the sum is at or above the limit a **new** client gets `503` with `Retry-After: 1` before a per-address slot is taken; connections that exist are not touched (a hard cap that closes live connections is a separate decision). New gauge `wsrv_buffered_bytes`, new counter result `wsrv_connections_total{result="rejected_buffer_budget"}`, new warn event `buffer_budget` (rate-limited). Each connection charges by difference through a ledger whose destructor refunds, so the counter cannot drift. Behaviour changes only above 1 GiB buffered, which at the defaults needs 512 connections each holding two full 1 MiB buffers; a host with a memory limit should set about half of it (`deploy/kubernetes/wsrv.yaml` sets 256 MiB for its 1 GiB limit). The C ABI is **1.1** for the new key (ADR-0016 A4: a minor adds keys; no symbol changes). OPERATIONS section 1.2.3, lesson 53.

- **An optional bearer token for the admin listener's `/metrics` page** (ADR-0041): `wsrvd` key `admin_token_file` (config file, `--admin-token-file`, `WSRVD_ADMIN_TOKEN_FILE`), a token `wsrvd --generate-token` made, mode 0600, different from the publish and IPC tokens, and `admin_port` set. `GET /metrics` then needs `Authorization: Bearer <token>` and answers one `401` for anything else (checked in constant time before the page is rendered); `/healthz` and `/readyz` stay open because probes cannot send a credential. Unset, nothing changes. A refusal is logged as the rate-limited warn event `admin_unauthorized`; with a token a non-loopback bind logs an info line instead of the `admin_exposed` warning. Embedders: `EmbeddedConfig::set_admin_token()` and `ServerBuilder::admin(ip, port, token)`; not a C ABI key (a secret does not belong in a `wsrv_config_set` string). A new fuzz target, `fuzz_admin_http`, asserts that the page is never rendered for a head that does not contain the token, and that every refusal is the same `401`. The publish endpoint and the admin listener now share one definition of "the credential of a request" (`http/bearer.hpp`: exactly one `Authorization` header, scheme `Bearer`, one space, no space or control character in the credential).

### Changed
- **BREAKING for a self-made publish token (ADR-0039).** From 1.1 `wsrvd` starts the publish endpoint only with a token that `wsrvd --generate-token=FILE` made, on every `publish_host` including loopback: a token you chose, however long, can be guessed, and the 32-byte floor could not tell the two apart. A 1.0 deployment whose `publish_token_file` was made with `openssl rand`, `head -c 32 /dev/urandom` or by hand stops at start with `config: from wsrv 1.1 the publish token must be one made by wsrvd --generate-token=FILE` (the token is never printed). Upgrade: as the service user, `mv publish.token publish.token.old && wsrvd --generate-token=publish.token`, restart `wsrvd`, give the new file to every publisher (the PHP `Publisher` only needs the new contents; the old token stops working at the restart). Docker Compose (`examples/docker`) replaces an old token by itself; Kubernetes: `kubectl create secret generic wsrv-secret --from-file=publish-token=publish.token` with a token made by the image, then `kubectl rollout restart`. The examples, the reference manifest, the systemd example and the guides now make the token this way. No back-off was added (a lockout lets anyone lock the real publishers out) and there is no switch to turn the rule off. The Unix-socket IPC token is unchanged. Chosen by the project owner over a warning in 1.1 and a requirement in 2.0.
- The official `wsrvd` image no longer sets `WSRVD_IPC_SOCKET`: its default socket path (`/run/wsrv/ipc.sock`) is built in and applies only when neither `ipc_socket` nor `ipc_port` is set, so `-e WSRVD_IPC_PORT=9300` alone selects TCP. Every existing way of running the image behaves as before. `wsrvd --healthcheck` does not probe a TCP IPC port.

## [1.0.0] - 2026-11-26

The first stable release. The owner decided (2026-11-23) that nothing is announced before the library is production-ready, so it was reached through `1.0.0-rc.N` pre-releases (`rc.1`, `rc.2`); what changed since `rc.2` is the runtime logger (ADR-0037), the Kubernetes manifest fixes, macOS client checks and the corrected documentation.

### Added
- **Runtime logging** (ADR-0037, NFR-O1 and NFR-O3): `wsrvd` and the embedded server write one structured `key=value` line per event to stderr (`ts level event conn peer suppressed dropped msg`), about 40 named events (`origin_refused`, `slow_consumer`, `ip_limit`, `app_connected`, `tls_reloaded`, `publish_rejected`, `conn_open`/`conn_close` at debug...). Settings `log_level` (`error`, `warn`, `info` default, `debug`) and `log_peer` (the client address in the lines, off by default because it is personal data), as flags, config keys and `WSRVD_LOG_LEVEL` / `WSRVD_LOG_PEER`. A peer cannot forge a line (everything it could influence is escaped; the messages carry nothing it sent), a flood of one event is held to a burst of 10 and then one line a second with `suppressed=N`, and a log destination that stops reading costs lines (`dropped=N`), never a stalled I/O loop. Event and field names are stable within 1.x. Before this the server counted problems on `/metrics` but never said which, when or why. See `docs/OPERATIONS.md` section 2.
- `.github/workflows/macos.yml`: the PHP package's test suite (PHP 8.2 and latest), the install helper as the real command and the JavaScript client's tests run on Apple Silicon macOS on every change; an informational, never-failing probe reports which C++ modules compile with Apple clang (the results are in DEPLOYMENT.md section 11). DEPLOYMENT.md section 11 documents macOS and Windows: develop with Docker Desktop or WSL2, run the worker beside the daemon, and what is planned for 1.x (TCP IPC, a native macOS server).
- `tools/coverage.sh` and `tools/coverage_report.py`: measure the line and branch coverage of `src/` against NFR-M4 and fail below a threshold. Run on 2026-11-26: 92.3 % of the lines, 85.4 % of the branches, every module above its threshold (docs/RELEASE.md section 4).
- `docs/LIMITS_AUDIT.md`: the 19 default limits of REQUIREMENTS section 4 checked against the code and the tests; three defaults that no test asserted are now asserted.
- The release job starts each architecture's image and waits for it to become healthy before scanning and pushing it, so the arm64 image is run too (ADR-0033 A1).
- The C ABI is **1.0** (`wsrv_abi_version()` was 0.4): no symbol changed; from here the major changes only with wsrv 2.0 and a minor only adds (ADR-0016 A4). The project and the PHP package are **1.0.0** in the sources; the tag decides release candidate or final.
- JavaScript client option `connectTimeout` (default 15 s, `0` = off): an attempt that has not opened by then, ticket call included, is abandoned and retried, so the client cannot stay in `connecting` whatever the platform does.
- `docs/BENCHMARKS.md` and `bench/compare/`: wsrv against Workerman 5, Swoole and Laravel Reverb (echo, idle memory, broadcast), with a four-CPU and a one-CPU run, the raw results, and a harness you can run yourself. Ahead with several cores (echo about 1.5 to 1.9 times, broadcast about 2 times), behind per core on echo (11 to 25 percent fewer messages per second on one CPU, after two fixes the benchmark prompted), equal on idle memory. Found three bugs and a performance problem in wsrv itself, all fixed (ADR-0016 A2, ADR-0034, ADR-0035, ADR-0036).
- The real client address behind a reverse proxy: `trusted_proxy` (addresses/CIDRs) and `client_ip_header` keys; the per-IP limits and the peer address in events then follow the client, not the proxy. Header ignored from untrusted peers, rightmost untrusted `X-Forwarded-For` entry, anything unusable falls back to the proxy address (ADR-0029). PROXY protocol is not implemented yet.
- Container and production operations (ADR-0030): every setting is a `WSRVD_<KEY>` environment variable (the base layer; flags and `--config` override it; an unknown `WSRVD_*` variable is a startup error), `wsrvd --healthcheck` (also the image's `HEALTHCHECK`), image defaults by environment, a hardened systemd unit and Kubernetes reference manifests under `deploy/`, and `docs/DEPLOYMENT.md`.
- Restarts are survivable (ADR-0031): `Wsrv\Supervisor` (the PHP worker reconnects to the daemon with exponential backoff and jitter, retries `BACKPRESSURE`, fails fast on a wrong token, reports a throwing handler without dropping the link, stops on `SIGTERM`), `Wsrv\ClusterPublisher` (publish to every daemon of a multi-node deployment, per-node failures reported) and `clients/js` (`WsrvClient`: browser/Node 22+ client with backoff, a fresh ticket per attempt and rooms re-joined after every reconnect), tested against a real `wsrvd` that is killed and restarted under a connected client.
- A byte budget for sends waiting for a loop (ADR-0032): `max_pending_send_bytes` (per loop, default 64 MiB, 1 B to 1 GiB). `SessionHandle::send_text/send_binary` return `BufferFull` (C: `WSRV_ERR_BACKPRESSURE`) when it is used up and `InvalidArgument` for a message larger than the whole budget. Closes the security review's item 4a.
- RFC 6455 WebSocket server: sans-I/O protocol core, handshake with Origin policy, frame codec, UTF-8 validation, fragmentation, close handshake, multi-loop epoll server, bounded queues with backpressure. Autobahn|Testsuite: 517 cases, 0 failed (plain and wss; C and PHP bindings too).
- permessage-deflate (RFC 7692) over system zlib, with a decompression-bomb guard.
- TLS (`wss://`) over OpenSSL, with certificate reload.
- Per-IP and global limits, descriptor budget check, Prometheus metrics and an admin listener.
- Pub/sub broker (topics and rooms) for C++ applications (ADR-0024).
- C ABI (`include/wsrv/wsrv.h`, ABI 0.4) and `libwsrv.so`, pull-model events, handshake authentication hook.
- `wsrvd` sidecar daemon and IPC protocol v0.
- PHP package: sidecar client and worker (pure PHP), embedded server over FFI (`Wsrv\Embedded\Server`) with the `authenticate` hook, echo and chat examples. Supports PHP 8.2 to the latest release (tested in CI).
- Composer package layout, `bin/wsrv-install-lib` (SHA-256 verified download of the native library) and a tag-triggered release workflow with checksums and build attestation (ADR-0026).
- Documentation set: requirements, architecture, ADRs, edge-case catalogue, 47 lessons.
- `wsrvd` container image (`docker/wsrvd.Dockerfile`, published to GHCR by `release.yml`, amd64 and arm64) and a Docker quickstart with a PHP worker (`examples/docker`), ADR-0026 amendment 1.
- Broker driven by connection id in the embedded server (`broker` and five `broker_max_*` config keys, ADR-0027 slice 1); the C ABI and PHP follow.

- Laravel integration guide (`docs/LARAVEL.md`), run against Laravel 13.
- PHP: `Connection::subscribe`/`unsubscribe`, `Worker::publish` (IPC 0.3) and `Wsrv\Publisher` for HTTP publishing (ADR-0028 slice 4); `wsrvd` reports the publish port.
- HTTP publish endpoint (`POST /publish`, bearer token file, bounded, off by default; `publish_port`, `publish_host`, `publish_token_file`), `wsrv_publish_http_total{status}`, ADR-0028 slice 3.
- IPC protocol 0.3: `SUBSCRIBE`, `UNSUBSCRIBE`, `PUBLISH` frames and the status `LIMIT`; the daemon drops a departed application's subscriptions at once (ADR-0028 slice 2).

### Changed
- The daemon's start-up lines are now log events: `wsrvd: websocket server listening on port N` became `event=listening` (with the port in `msg`), `ipc socket ... ready` became `event=ipc_ready`, and the SIGHUP lines became `tls_reloaded` / `tls_reload_failed` / `tls_reload_skipped`. Nothing had been released with the old text; a script that waited for it must wait for `event=listening`. Mistakes in the command line itself are still printed plainly with the usage text.
- REQUIREMENTS section 4, two rows reworded to say what the code does (the audit found the code on the safer side): over the global connection cap the connection is closed at accept with no answer (there is no 503); the inbound read buffer is 16 KiB per event loop, shared, and a connection holds only its unfinished frame.
- The install lines in the README, the Laravel guide, the PHP README and `examples/docker` name `1.0.0-rc.1` until the final release (no `0.1.0` release was ever published); the Docker example's worker runs under `Wsrv\Supervisor`.

### Fixed
- `wsrv-install-lib` no longer writes a Linux library on a system that cannot load it: on Apple Silicon `php_uname('m')` is `arm64`, which it mapped to aarch64, so a Mac would have received a Linux ELF file. It now stops first and names the system, says the server is Linux only and what to run instead (the Docker image; the PHP client works there).
- `.github/workflows/kubernetes.yml` applies the Kubernetes reference manifest to a real (kind) cluster on every change to it, the daemon or the image, with the image built from the same commit. It is how the next item was found and proved.
- The Kubernetes reference manifest could not start: `wsrvd` refuses a token file that is group-readable or owned by another user, and a Secret volume is both. An init container now copies the token into the in-memory pod volume as the daemon's user, mode 0600 (checked against the published image with the manifest's uids and modes); the manifest also sets `enableServiceLinks: false` and a `preStop` sleep so a rolling update does not refuse upgrades while the ingress still routes to the old pod. DEPLOYMENT.md says the same for Docker/Swarm `secrets:` mounts.
- `wsrvd` and `wsrvd --healthcheck` no longer stop at start when Kubernetes service-link variables of a Service named `wsrvd` (`WSRVD_SERVICE_HOST`, `WSRVD_PORT=tcp://...` and the like) are in the environment; any other unknown `WSRVD_*` variable is still an error (ADR-0030 A1).
- The JavaScript client stopped reconnecting after the first failed attempt on Node 22: its built-in WebSocket (undici 6.x, the official `node:22` images) fires `error` for a failed handshake and never `close`, and the client waited for the `close`. An error before the socket opens now ends the attempt and the client backs off and retries; `close()` called from a `close` listener no longer lets a retry through. Found by the soak test: all 50 clients were still stuck 5 minutes after one daemon restart (ADR-0031 A1).
- On a busy server `wsrvd` woke its IPC thread once per message: every message queued for the host cost an eventfd write and read, a futex wake and two context switches, and nothing was batched when the loop and the IPC thread shared a core. With everything pinned to one CPU the echo throughput was 50 percent below single-process PHP servers. The loop now pays the host's wake-up once per loop iteration for all the messages it queued (`EventQueue::Wake::AtFlush`, `EventLoop::set_iteration_end`, `IHandlerFactory::on_loop_iteration_end`). One-CPU echo: 53 600 to 82 800 messages per second (+54%), median latency 9.6 to 5.9 ms; Open, Close and the other rare events still wake the host at once (ADR-0035). Found by the one-CPU run of the 1.0 benchmark.
- Two system calls per message that carried no information are gone: the `read` that only answers "would block" after a short read on a plain socket (never after a hang-up, never for TLS), and the `getpid()` that the embedded API ran on every `poll` and `send` to detect a `fork()` (now a `MADV_WIPEONFORK` page, with the `getpid()` check as the fallback). One-CPU echo: about 95 000 to 103 000 messages per second (+8%) (ADR-0036).
- A broadcast to a big room lost recipients, and closing the connections of a lost worker left some open: both posted one task per connection to a loop queue of 4096 slots (3072 for bulk). With one I/O thread a 5000-subscriber room received 61% of every broadcast; with 5000 connections on one loop and the worker killed, 904 stayed open for good. A broadcast now takes one slot per chunk of 256 recipients, refused closes are retried every 25 ms, and the broker's rotation moves by a chunk (ADR-0034). Found by the 1.0 benchmark.
- The server held at most 4095 concurrent connections whatever `max_connections` said (default 10 000): every live connection reserves a slot of the 4096-event host queue for its Close, and the 4096th was accepted, upgraded and then closed. The queue defaults now follow `max_connections` (ADR-0016 A2); `event_queue_events` / `event_queue_bytes` set by hand still win. Found by the 1.0 benchmark (5 000 idle connections lost 905).
- permessage-deflate: an offer that repeats a parameter is declined (RFC 7692 section 7) instead of failing the handshake; a message ended by a final block is accepted and keeps its window, with one restart per message.
